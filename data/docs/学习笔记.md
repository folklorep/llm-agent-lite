## 💻 三、算法（LeetCode）

### 1. 两数之和 —— 字典 "名单" 套路 ⭐核心



```
def twoSum(nums, target):

&#x20;   seen = {}                        # 名单：数 → 下标

&#x20;   for i in range(len(nums)):

&#x20;       need = target - nums\[i]      # 我需要谁？

&#x20;       if need in seen:             # 名单里有吗？

&#x20;           return \[seen\[need], i]   # 有！返回老朋友下标 + 当前下标

&#x20;       seen\[nums\[i]] = i            # 没有 → 登记自己（先查后登记！）

&#x20;   return \[]                        # 找不到兜底
```

**关键**



* **先查后登记**：防止自己配自己（`[2]` + target=4 的场景）

* 为什么比暴力快：查字典是瞬间的，不用回头找

### 2. 有效的括号 —— 栈（后进先出）⭐



```
def isValid(s):

&#x20;   pairs = {")": "(", "]": "\[", "}": "{"}

&#x20;   stack = \[]                       # 一摞盘子

&#x20;   for ch in s:

&#x20;       if ch in pairs:              # 右括号

&#x20;           if not stack:            # ① 栈空 → 无左括号可配

&#x20;               return False

&#x20;           if stack\[-1] != pairs\[ch]:   # ② 栈顶不匹配（交叉嵌套）

&#x20;               return False

&#x20;           stack.pop()              # ③ 匹配 → 弹出

&#x20;       else:

&#x20;           stack.append(ch)         # 左括号 → 压栈

&#x20;   return len(stack) == 0           # ④ 清点：栈空才有效
```

**关键**



* 栈 = 一摞盘子：后进先出；Python 里 = 列表 + `append` + `pop` + `stack[-1]`

* 三道防线：空栈 / 栈顶不匹配 / 最后清点（左括号剩了没配完）

### 3. 第一个重复数字 —— 查重（名单套路变体）

def first\_duplicate(nums):

&#x20;   seen = {}

&#x20;   for x in nums:

&#x20;       if x in seen:

&#x20;           return x        # 见过 → 返回它

### 4. 合并两个有序链表 —— 链表（假头）⭐ 第 2 个数据结构

链表 = 一列手拉手的车厢：每个节点只有 `val`（货）+ `next`（下一节是谁），最后是 `None`。
- **没有下标**：不能 `data[2]`，只能从头顺着 `next` 一个个走
- 节点：`class ListNode: __init__(self, val, next)`，`self.next` 默认 `None`
- 遍历：`cur = head` → `while cur is not None:` → `cur = cur.next`

```python
# LeetCode 21 提交版
class Solution:
    def mergeTwoLists(self, l1, l2):
        dummy = ListNode()      # 假头：占位空节点，让"接第一个"和"接第N个"写法统一
        prev = dummy            # 游标：新链表当前接到的位置
        p1, p2 = l1, l2         # 两个旧链表的"当前车厢"

        while p1 is not None and p2 is not None:
            if p1.val <= p2.val:   # p1 更小 → 接 p1
                prev.next = p1
                p1 = p1.next
            else:                  # p2 更小 → 接 p2
                prev.next = p2
                p2 = p2.next
            prev = prev.next       # 游标前进

        prev.next = p1 if p1 is not None else p2   # 一方走完，剩余整串直接挂上
        return dummy.next          # 跳过假头，返回真头
```

**关键**
- **假头 dummy** = 占位空节点（排队领队），避免特判"第一个节点"，最后 `return dummy.next`
- 拉链法：谁小谁先上
- **LeetCode 提交规则**：函数必须放 `class Solution:` 里 + 参数带 `self`；`class ListNode` 不要贴（已内置）

| 模式    | 场景                  | 关键动作                              |
| ----- | ------------------- | --------------------------------- |

## 🤖 四、机器学习基础

### 第 1 讲：概念框架



* **机器学习** = 不靠人写规则，程序从 "历史例子" 里自己找规律，再用规律预测新东西

* 流程：数据 → 训练（找规律）→ 模型（规律本身）→ 预测



| 术语 | 意思     | 例子（预测下雨）            |
| -- | ------ | ------------------- |
| 特征 | 已知的输入  | 气温、湿度、气压、云量、风速、季节   |
| 标签 | 要猜的输出  | 明天是否下雨（是 / 否）       |
| 训练 | 喂数据找规律 | 喂几百条 "特征→答案"        |
| 模型 | 学出来的规律 | "湿度高 + 气压低 → 大概率下雨" |

**判断标准**



* 数据**有答案（标签）** → 监督学习；没答案 → 无监督学习

* 监督里：答案是**类别** → 分类；答案是**数字** → 回归

* 经典坑：手写数字 0-9 识别是**分类**（10 个固定选项），不是回归

* 数据泄漏：特征里不能含结果（"天气" 不能当 "预测是否下雨" 的特征）

### 第 2 讲：线性回归 + 损失函数 ⭐第一段 ML 代码



```
import numpy as np

hours = np.array(\[1, 2, 3, 4, 5])

scores = np.array(\[50, 60, 70, 80, 90])

def predict(hours, w, b):          # 模型：一条直线

&#x20;   return w \* hours + b

def loss(hours, scores, w, b):     # 损失函数：MSE 均方误差

&#x20;   pred = predict(hours, w, b)

&#x20;   return np.mean((pred - scores) \*\* 2)

print(loss(hours, scores, 10, 40))   # 0.0（完美）

print(loss(hours, scores, 9, 41))    # 6.0（还行）

print(loss(hours, scores, 2, 20))    # 2730.0（离谱）
```

**关键**



* 模型：`预测分 = w × 时长 + b`（w = 斜率，b = 截距）

* **损失函数 = 模型的错题率**：衡量 "预测 vs 真实" 差多少；训练 = 让损失变小

* 训练的本质：疯狂试 w、b，找损失最小的那一组（以后学梯度下降自动调）

### 第 3 讲：梯度下降 ⭐训练的核心引擎（9/15 完成）

**蒙眼下山比喻**：站在山坡上（损失高地），蒙眼摸坡度，朝下坡方向迈一小步，重复，直到谷底（损失最小）。

| 下山比喻 | 术语 | 代码 |
|---|---|---|
| 山的高度 | 损失函数 | `(w-3)²` |
| 你的位置 | 参数 w | `w` |
| 脚下坡度 | 梯度（导数） | `2*(w-3)` |
| 每步迈多大 | 学习率 lr | `0.1` |
| 走到谷底 | 训练完成 | 损失≈0 |

```python
w = 0.0
lr = 0.1
for step in range(20):
    grad = 2 * (w - 3)        # 当前坡度（导数）
    w = w - lr * grad         # 朝下坡方向走一步 ← 核心公式
    loss = (w - 3) ** 2
    print(step + 1, round(w, 3), round(loss, 4))
```

**关键**
- **核心公式**：`w = w - lr * grad`——顺着梯度反方向（下坡）更新参数
- **收敛规律**：越接近谷底坡度越小、步子越小 → w 无限逼近最优解但不精确等于（2.965 ≠ 3，正常）
- **学习率三档**：太小（龟速）、合适（0.1 二十步到）、**太大（发散）**——lr=1.5 时 w 正负横跳、损失每步 ×4 指数爆炸
- 面试点：学习率太大/太小会怎样？——发散 / 太慢不收敛

### 第 3 讲补充：两参数梯度下降 + 特征标准化（9/15 完成）

**目标**：让程序自动找线性回归的 w、b（替代手动试），w=10, b=40 闭环。

**坑**：原始数据 x∈[1,5]、y∈[50,90] 量级差 20 倍 → w、b 梯度尺度不匹配 → 之字形爬坡，300 步不收敛。

**解法：特征标准化**（ML 标准操作）
```
mean = Σv / N
std  = √( Σ(v−mean)² / N )
z    = (v − mean) / std      # 标准化后：均值 0、标准差 1、量级 ±1.4
```

**效果**：标准化后 50 步 loss 归零（每 5 步缩小约 10 倍，指数收敛），w→1, b→0。还原回原始数据：w=10, b=40 = 第 2 讲手动最优解 ✅ 三讲闭环！

**两参数同时更新**：
```python
grad_w = 2/N * sum(x_i * err_i)   # 对 w 的坡度
grad_b = 2/N * sum(err_i)         # 对 b 的坡度
w = w - lr * grad_w
b = b - lr * grad_b
```

**面试点**：特征量级差太多会怎样？→ 梯度下降收敛慢（之字形）；解法 = 标准化。

resp = requests.post(API_URL,

### 项目 L2：多轮对话（9/23 完成 ✅）

**核心认知（面试常考）**：**大模型没有记忆**！每次调用都"失忆"。多轮对话 = 开发者自己把聊天历史（history 列表）拼进 `messages`，每轮重新发一遍。

```python
history = []   # 聊天记录本
def chat(user_input):
    history.append({"role": "user", "content": user_input})      # ① 你的话进记录
    resp = requests.post(API_URL, headers={"Authorization": f"Bearer {API_KEY}"},
        json={"model": "deepseek-v4-flash", "messages": history})  # ② 发完整记录
    answer = resp.json()["choices"][0]["message"]["content"]
    history.append({"role": "assistant", "content": answer})     # ③ AI 的话进记录
    return answer
```

**为什么历史越长越贵**：计费按 token 算，每轮都重新发送整个 history → 第 N 轮发送量 ≈ 2N-1 条 → 长对话成本二次方增长 → 这就是"花钱买额度"的原因之一。

**真实应用解法（上下文管理，面试八股）**：滑动窗口（只留最近 N 轮）/ 历史摘要（压缩前面）—— L3/L4 学。

### 项目 L3：角色扮演 / 系统提示词（9/23 完成 ✅）

**第三种 role：`system` = 人设说明书**，放在 messages 最开头，只有开发者能写（用户改不了）。AI 每轮先读人设再回答。

```python
SYSTEM_PROMPT = "你是一位严格的AI算法面试官……"
history = [{"role": "system", "content": SYSTEM_PROMPT}]   # 记录本第一页 = 人设
```

**核心认知（面试重点）**：**同一模型，换一行 system prompt 就换一种行为**（面试官 → 英语老师）。大模型时代"改提示词 = 改行为"，不训练零成本 —— 这就是大模型应用开发 vs 传统 AI 的区别。

**真实产品**：客服机器人（人设=客服规范）、面试辅导（人设=面试官，✅ 已实测）、文案助手（人设=小红书风格）。

**提示词工程技巧（面试八股）**：角色设定 → 明确要求（格式/长度）→ few-shot 给示例 → 思维链（让它一步步想）—— L4 继续。

### 项目 L4：RAG 问答（检索增强生成）（9/23 完成 ✅）

**RAG = 给模型开卷考试（先翻书，再答题）**：
```
Retrieval 检索 → 在资料库找相关片段
Augmented  增强 → 把片段拼进 prompt（"严格根据资料回答，不要编造"）
Generation 生成 → 模型照着资料回答
```

**为什么需要**：模型不知道你的私有资料，直接问会**幻觉**（瞎编）。

```python
knowledge = [{"tag": "两数之和", "text": "..."}, ...]   # 资料库
def search(query):     # ① 关键词匹配检索
    return [item["text"] for item in knowledge if item["tag"] in query]
# ② 拼 prompt：f"请严格根据以下资料回答，不要编造资料外的内容：{context}{question}"
# ③ requests.post 生成
```

**实测（9/23）**：问"两数之和"→ 答"先查后登记"（来自资料）；问"红烧肉"→ 如实说不知道（**防幻觉 ✅**）。

**简历写法**："基于 DeepSeek 的 RAG 知识问答助手：私有资料检索 + 防幻觉回答"。

**进阶（真实 RAG）**：检索用**向量相似度**（embedding，而非关键词）→ 向量数据库（如 faiss/chroma）→ 配合多轮对话 —— L5 / 项目二期。

### 项目 L5：Function Calling / 智能体（9/28 概念课 ✅，9/29 实操完成 ✅）

**一句话**：Function Calling = 让大模型能调用你写的函数——从"会说话"到"能干活"，智能体的第一步。

**顾问比喻**：模型 = 判断要不要用工具的"顾问"；你的代码 = 执行工具的"助理"；**顾问 + 助理 + 循环 = 智能体（Agent）**。

**模型三个死穴（为什么需要工具）**：不会精确计算 / 没有实时数据 / 不能操作外部系统 → 全靠工具函数补。

**四步流程（核心）**：
1. 声明工具箱：把函数清单（名字+参数）告诉模型
2. 模型"点单"：模型返回"我要调用 compute(3.14, 17)"，不直接回答
3. 代码执行：你的程序真去调用函数（算数/查天气/查库）
4. 结果回传：执行结果塞回对话，模型照结果给最终答案

**关键认知**：模型只"点单"不"动手"——它是指挥官，你的函数是执行者，动手的永远是代码。

**9/29 实操成果（chat.py 已跑通）**：

**实操踩坑四连（面试素材）**：
1. **模型名过期**：deepseek-v4-flash 已下线 → 必须用 deepseek-flash（旧名仍可调但模型已退役，行为退化）；要常看官方文档

3. **模型"演"工具调用**：模型偶尔不返回 JSON 协议，而是把调用"演"成文本标签 → prompt 明确"不要输出任何调用代码/标签/标记文本"；代码只认标准 JSON tool_calls
4. 环境坑：多 Python 版本并存（3.12 有 requests / 3.13 没有）→ **黄金规则：永远用 `python -m pip install 库名`**，保证装进 python 命令对应的版本

data = np.array(\[

## ⚠️ 八、易错点清单（错题本）



1. `score1、score2...` 坏味道 → 用列表

2. `sum(x)` 不 print 不显示结果

3. 一行只能一条语句（除非分号）

4. 函数没 return 时 `print(func())` 会输出 `None`

5. 平均分要放**循环外**算一次，别在循环里每轮重算

6. 字典：创建用 `{}`，取值用 `[]`

7. `for i in range(...)` 拿下标；`for x in list` 拿元素 —— 拿到元素别再 `nums[x]`（IndexError）

8. 先查后登记（防自己配自己）

9. 手写数字识别是**分类**不是回归

10. 有标签才能监督学习；特征不能含结果（数据泄漏）

11. 变量名别用 `list`、`dict`、`sum`（覆盖内置功能）

12. `range(n)` 包前不包后（没有 n）；下标最大 `len-1`

13. **LeetCode 提交**：函数要放进 `class Solution:` 里 + 参数带 `self`，否则报 `NameError: 'Solution' is not defined`；`class ListNode` 别贴（已内置）

14. 本地测链表**不能用列表**，要用 `ListNode` 串起来；链表打印要自己遍历

15. **有效的括号三连坑**：① 左括号也被送去"检查" → 第一轮必 False（必须分岔：左压栈、右检查）② 配对表方向决定查表对象：左→右用 `pairs[stack[-1]]`，右→左用 `pairs[char]` ③ 匹配成功后**忘了 `pop()`** → 栈永远不清空
